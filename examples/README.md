# Fictional record examples

[Handbook](../docs/README.md) · [Worked walkthroughs](../docs/examples.md)

These are newly written illustrative records. Names, IDs, machine labels, commands, and outcomes
are invented. They do not contain private cases or production data and are not a runnable copy
of the framework. Real IDs must come from the allocator.

| File | Shows |
|---|---|
| [intent.md](intent.md) | Outcome, criteria, and lifecycle header |
| [triage.md](triage.md) | Manual proceed/background assessment |
| [log.md](log.md) | Dated history and verification wording |
| [friction.md](friction.md) | Toil entry, case, detector, remedy, residual |
| [win-draft.md](win-draft.md) | Positive evidence before validated publication |
| [card-feed.json](card-feed.json) | Small version-1 Kerdr feed |
| [card-action.json](card-action.json) | JSON action data, not shell text |

Example detector/test paths are explanatory placeholders. The win draft's tags must be replaced
with valid tags from a real installation before submitting it to that installation's validator.
